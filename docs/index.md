## Project Overview

- **Type:** Monolith (single Go module `github.com/petabytecl/scrap`)
- **Primary Language:** Go 1.26.4
- **Project Type:** Backend service — transaction-scoped document storage gateway
- **Architecture:** Layered, service-oriented monolith over a per-Shard Raft
  storage engine (gRPC public/peer APIs + admin HTTP)

## Quick Reference

- **Tech Stack:** Go · etcd raft v3 · Pebble · gRPC/buf · OpenBao Transit ·
  OpenTelemetry · AWS S3 SDK v2
- **Entry Points:** `cmd/scrapd` (service), `cmd/scrapctl` (operator CLI)
- **Composition Root:** `internal/cmd` (`App.Run` / `newApp`)
- **Scale:** 391 Go files, ~92k LOC, 26 `internal/` packages
- **Surfaces:** Public gRPC `:9090` · Peer gRPC `:9091` · Admin HTTP `:8080`

## Getting Started

1. Read `CONTEXT.md` (glossary + invariants), then [Architecture](./architecture.md).
2. Build: `make build`. Verify: `make tier1-check`.
3. Run tests at the narrowest tier that proves your change
   (see [Development Guide](./development-guide.md)).
4. Production package changes must trace to a PRD/story/ADR/issue; storage-format,
   wire, dependency, security, or cross-package changes require an ADR in
   `docs/adr/`.

## Notes for Brownfield Planning

When creating a brownfield PRD or planning new features, point the PRD workflow
to this index (`docs/index.md`). For storage/consensus changes, also reference
[Architecture](./architecture.md) §4–§9 and the relevant ADRs.
