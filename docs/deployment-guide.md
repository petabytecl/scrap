# Deployment Guide — S.C.R.A.P.

_Generated by the document-project workflow (exhaustive scan), 2026-06-21._

S.C.R.A.P. deploys as a **Cell** — one complete deployment per Kubernetes
cluster, running `scrapd` Members as a StatefulSet. This guide summarizes the
container image, Kubernetes topology, and the Make-driven deployment flows. ADR
0015 and ADR 0024 govern the prod-like Cell, Cilium, and topology policy.

## Container Image

`Dockerfile` builds `scrapd` with `CGO_ENABLED=0`, `FROM scratch`, running as
non-root `65532:65532`, entrypoint `/scrapd`. **No shell, package manager,
dynamic libraries, or runtime tools exist in the image** — do not assume them.
A `healthcheck` subcommand is built into the binary (`scrapd healthcheck ...`).

```sh
make image            # cross-compile scrapd + docker build (localhost/scrapd:local)
```

Image release metadata is injected via ldflags (`version`, `buildSHA`,
`buildTime`).

## Kubernetes Topology

One Cell per cluster (`CONTEXT.md`, ADR 0024):

- **StatefulSet** of `scrapd` Members, **one PVC per Member** (durable
  `member_id` on the volume).
- **Headless Service** for peer DNS:
  `<member_hostname>.<headless_service>.<namespace>.svc.<cluster_domain>:<peer_port>`.
- **Separate listeners/ports** — public gRPC, peer gRPC, admin HTTP.
- **NetworkPolicies** (Cilium) restrict peer + admin traffic.
- **Peer discovery** — K8s-first: pod ordinal → Raft node ID (ordinal + 1);
  configured via `SCRAP_REPLICAS`, `SCRAP_HEADLESS_SERVICE`, `SCRAP_CELL_ID`,
  `SCRAP_PEER_PORT`.

## Deployment Assets (`deploy/`)

```
deploy/
├── kind/                 # Kind cluster configs: cluster.yaml, cluster-prodlike-cilium.yaml, cluster-stress.yaml
├── cilium/               # Vendored Cilium chart + prodlike-values.yaml
├── kustomize/
│   ├── base/             # Base manifests
│   ├── components/       # evidence-stack, external-openbao-transit, localstack,
│   │                     #   monitoring, nodeports, scrub-fast, stress-tuning
│   ├── environments/     # local, local-scrub, prodlike, prodlike-e2e,
│   │                     #   prodlike-openbao, evidence
│   └── overlays/         # local-kind, prodlike, prodlike-e2e, evidence, monitoring, ...
└── aws/validation/       # AWS deployment validation assets
```

Manifest hardening invariants are validated by
`scripts/check-kustomize-manifests.sh` (via `make manifests-check`) and
`scripts/check-kind-cilium.sh` (via `make kind-cilium-check`).

## Deployment Flows

### Local Kind (development)

```sh
make local-dev-up        # start local dev environment
make local-dev-status    # show resources + port-forwards
make local-dev-down      # stop + delete kind cluster

make e2e-up              # create Kind, load image, deploy local overlay, run E2E
make e2e-down            # delete the local Kind Cell
```

The local flow also deploys LocalStack and ensures the S3 bucket
(`SCRAP_E2E_S3_BUCKET`, default `scrap-e2e`) exists for Backend upload paths.

### Prod-like Kind Cell (Cilium-backed)

```sh
make prodlike-up         # create Kind + Cilium, load image, deploy, doctor
make prodlike-doctor     # health check without (re)creating infra
make prodlike-down       # delete the prod-like Cell
```

The prod-like Cell installs the vendored Cilium chart, applies the `prodlike`
Kustomize environment, brings up LocalStack, and waits for the `scrapd`
StatefulSet to be Ready.

### Tier 2 E2E (security-hardened)

```sh
make tier2-e2e-up        # bring up prod-like Kind with E2E hooks, run Tier 2 gate
```

Tier 2 runs with `SCRAP_SECURITY_MODE=test` and full mTLS material generated by
`scripts/prodlike-test-security-assets.sh`. It requires `SCRAP_TEST_HOOKS=1`,
which is permitted **only** on prod-like E2E overlays — never production.

### Evidence / Stress (Tier 3)

```sh
make evidence-up         # bring up evidence Cell (observability stack first, then app)
make stress              # run stress generator (throughput|mixed|pressure)
make evidence-bundle     # generate timestamped evidence bundle
make tier3-evidence-up   # evidence Cell + Tier 3 gate
make evidence-down       # delete evidence Kind Cell
```

The stress setup deploys the OTel evidence stack (Loki, otel-collector/agent,
Mimir, Tempo, Pyroscope, Alloy, Grafana, kube-state-metrics) before the
application so logs are captured from the first line. Default endpoints:
gRPC `127.0.0.1:18090`, Grafana `http://127.0.0.1:13000`, OTLP collector
`127.0.0.1:14317`, LocalStack `http://127.0.0.1:18566`.

## Production Security Requirements

- **mTLS** material per surface via `SCRAP_TLS_{PUBLIC,PEER,ADMIN,SCRAPCTL}_*`.
- **OpenBao Transit** envelope encryption (`SCRAP_TRANSIT_*`); production paths
  fail closed on key-material failure. See `docs/openbao-deployment-contract.md`.
- **Startup gates** (`internal/security`) reject insecure production
  configurations before any listener/Backend opens.
- **No test hooks / unauthenticated pprof** in production or prod-like
  production overlays.

## Operations

Operator tooling is `scrapctl` (`docs/api-contracts.md` §4) and the runbooks
under `docs/runbooks/` (backend upload pressure, block/content quarantine,
eviction campaigns, evidence collection, mTLS rotation, multi-shard routing,
OpenBao transit dependency, restore failures, startup security readiness).

```sh
scrapctl doctor          # cluster + runtime health
scrapctl status          # Cell status
scrapctl upload-pressure # Backend upload admission pressure
scrapctl peers | leader  # membership / leadership
```
