# Architecture — S.C.R.A.P.

_Generated by the document-project workflow (exhaustive scan), 2026-06-21._

This document describes the as-built architecture of S.C.R.A.P., a
transaction-scoped document storage gateway. It complements `CONTEXT.md` (the
canonical glossary and process contract) and the 27 ADRs under `docs/adr/`,
which carry the authoritative rationale for hard-to-reverse decisions.

---

## 1. Executive Summary

S.C.R.A.P. accepts immutable Documents over gRPC, groups them by Transaction,
packs their bytes into append-only Blocks, replicates bytes to peer Members,
commits metadata through per-Shard Raft consensus, and asynchronously uploads
sealed Blocks to a Backend object store. Reads are verified all-or-error and
served from the nearest checksum-valid replica.

Core principles:

- **Metadata is authority; the projection is derived.** Raft holds the truth for
  Document visibility and physical references; Pebble is rebuildable (ADR 0001).
- **Bytes never enter Raft.** Raft carries ~330-byte metadata commands + trace
  context; peer gRPC carries byte replication and Block transfer.
- **Fail closed on corruption.** No read returns partial or unverified bytes.
- **ACK ≠ Backend durability.** Documents are ACK'd from local + peer replica
  durability; Backend upload is an asynchronous obligation.

## 3. Architectural Pattern

A **layered, service-oriented monolith** built around a single composition root.
`internal/cmd` is the only package that wires subsystems; feature packages
expose narrow options/interfaces and avoid importing each other directly.
Consumer-defined interfaces keep core storage/consensus packages free of
transport concerns (no `grpc/status`/`grpc/codes`, enforced by
`make package-boundaries`).

### Process surfaces (`internal/cmd/app.go`)

`scrapd` serves three independent surfaces concurrently; `App.Run` waits on the
first failure or context cancellation, then performs an ordered `Shutdown`
(`admin → peer gRPC → peer writers → client gRPC → shard → peer client →
transport → telemetry`).

## 4. Storage Engine (`internal/shard`)

`internal/shard` is the largest package and implements the `store.Store`
contract. It owns:

- **Write path** — block writer + index writer, Openlog prepare records,
  peer fan-out, Raft proposal, projection apply.
- **Raft apply handler** — deterministic application of `RaftCommand`s;
  atomic applied-index + projection update in one `Batch.Commit()` (avoids the
  V1 `appliedIndex` vs `durableLogIndex` stranding bug).
- **Projection rebuild** — wipe + replay from Raft state.
- **Scrub coordination** — schedules light/deep scrub via `internal/scrub`.
- **Backend upload** — watches the Upload Outbox, uploads sealed Blocks.
- **Eviction, rewrap, quarantine** — leader-driven lifecycle operations.

Multi-Shard placement is fixed-slot (`hash(transaction_id) % 1024 → slot →
Shard`, `internal/routing`). A single-shard fallback topology exists; some peer
RPCs (consistency/rebuild) and light scrub are exposed only when the local Shard
is unambiguous, because those RPCs do not yet carry a Shard ID.

## 5. The Write State Machine (7 states)

A write moves through seven semantic states (`CONTEXT.md`). Client ACK returns
at **state 5 (Visible)**; Backend upload (states 6–7) is outside the ACK path.

```
1 Accepted → 2 Local bytes durable → 3 Peer bytes durable →
4 Metadata committed → 5 Visible (*** ACK ***) →
6 Backend upload recorded → 7 Backend uploaded & verified
```

Implementation ordering (spike-validated):

```
1. local Block bytes → fsync                 (→ state 2)
2. Openlog .prep record → fsync              (→ state 2 sealed)
3. required peer prepare                      (→ state 3)
4. Raft metadata command on quorum            (→ state 4)
5. projection commit (derived)                (still state 4)
6. client ACK + read visibility               (→ state 5)
```

Leadership loss mid-write returns `ErrNotLeader`; the `.prep`/Block bytes are
left for Openlog recovery, which truncates partial writes uniformly.

## 6. Read Path

Leader-only reads (Phase 2 safety milestone; ReadIndex from followers is a known
extension). The Projection maps Transaction → Block IDs; the `.idx` resolves
per-Document metadata. `ReadDocument` is two-pass and bounded-memory:

1. **Pass 1** — verify Frame headers, payload CRCs, sequence, frame count, and
   Document SHA-256.
2. **Pass 2** — stream verified bytes only.

Corrupt reads emit zero messages and return `DATA_LOSS`. Non-leader members
return `UNAVAILABLE` with a `LeaderHint` detail; the smart client redirects.

## 7. Replication & Consensus

- **Byte replication** — leader fans out frames to peers via `PeerService`
  (`ReplicateDocument`); bytes reach quorum Members before the Raft metadata
  commit (ADR 0001). `TransferBlock` handles recovery/catch-up.
- **Raft** — `internal/raft` wires the etcd/raft node, StatefulSet ordinal
  discovery, K8s peer-set construction, and the gRPC raft transport
  (`ForwardRaft`/`ForwardRaftStream`). WAL/snapshots use the etcd WAL & snap
  libraries; Raft state is separate from the projection.
- **Bootstrap** — K8s-first auto-discovery: ordinal 0 bootstraps the group; other
  ordinals wait to be added; existing WAL resumes. `--peers` overrides for dev.

## 8. Integrity & Repair

- **Light scrub** (daily) — leader proposes `RequestConsistencyCheck`; voters
  compute a streaming SHA-256 over projection keys at the same applied index;
  divergence triggers projection wipe + Raft replay on the divergent voter.
- **Deep scrub** (weekly) — each voter re-verifies sealed Block bytes (Frame
  CRC-32C + Document SHA-256); corrupt Blocks are quarantined
  (`.blk.quarantine`) and re-fetched via `TransferBlock`. I/O is token-bucket
  rate-limited (default 125 MB/s) and pauses when read p99 exceeds threshold.
- **Content Scanner** (`internal/avscan`) — async malware scan of sealed Blocks
  after ACK; flags Documents via `QuarantineDocument` (Content Quarantine,
  ADR 0025), distinct from Block Quarantine.

## 9. Backend Upload & Lifecycle

Leader-only upload of sealed Blocks (`.blk` + `.idx` as separate objects,
ADR 0009). Verified via HEAD + size/ETag before proposing `ConfirmUpload`.
The **Upload Outbox** (materialized from `SealBlock` without matching
`ConfirmUpload`) drives three-level admission pressure (WARN/PRESSURE/CRITICAL)
to bound local disk usage. Phase 4 partial eviction lets followers drop `.blk`
while retaining `.idx` for metadata reads (ADR 0016–0018). Phase 5 enables
restore-first cold reads (ADR 0027).

## 10. Security Architecture (ADR 0019, 0020, 0024)

- **Startup gates** (`internal/security`, enforced in `newApp` before any
  serving surface or Backend opens): security mode, mTLS material per surface
  (`SCRAP_TLS_{PUBLIC,PEER,ADMIN,SCRAPCTL}_*`), role policy, peer-identity
  policy, Transit config, audit/rate-limit policy, test-hook/pprof gating.
- **Surface separation** — public/peer/admin are distinct listeners with
  distinct authz; peer authorization verifies role + Cell + Member identity +
  Shard membership.
- **Envelope encryption** — OpenBao Transit (`internal/encryption`); production
  paths fail closed on key-material failure. Durable, idempotent rewrap
  (`RewrapDocumentEnvelope`, ADR 0021).
- **Telemetry privacy** — identifiers hashed by default; raw IDs only in the
  reserved local non-production Cell (`internal/telemetry`, ADR 0013 §4).

## 11. Observability (ADR 0012)

OpenTelemetry producer contract: low-cardinality metrics
(`scrap.<subsystem>.<measurement>`), structured slog JSON logs, traces, and
runtime profiles. A collector layer enriches K8s/SCRAP resource attributes,
batches exports, and tail-samples traces. No raw `transaction_id`/
`document_name`/idempotency keys/Backend keys as labels.

## 12. Deployment Topology

One **Cell** per Kubernetes cluster: a StatefulSet of `scrapd` Members, one PVC
each, a headless Service for peer DNS, separate public/peer/admin ports, and
NetworkPolicies (Cilium) restricting peer + admin traffic. See
`docs/deployment-guide.md` and `deploy/`.

## 13. Key Cross-Cutting Invariants

(From `CONTEXT.md`; structurally enforced where possible.)

1. No acknowledged write may be lost.
2. No read may return corrupt bytes (all-or-error).
3. No read may return an unacknowledged Document.
4. No silent divergence between replicas.
5. Metadata is the authority for existence (projection in Phase 1, Raft in 2+).
6. Logical (client) errors must not fail-closed shard-wide; only infrastructure
   errors may.
7. Conflict checks run on the apply side, not pre-batch (first-writer-wins).
