# Decision Log

This file records decisions, assumptions, and overrides made while creating
`prd.md`.

## DL-001: Headless fast-path creation

Decision: Create the PRD in headless fast-path style from the existing repo
context, Party Mode output, and source documents.

Rationale: The user approved "do it" after the BMad help and Party Mode
recommendation. The AskUserQuestion tool required by local AGENTS guidance is
not available in this environment, and the unresolved scope can be represented
as explicit decision gates instead of blocking artifact creation.

Impact: `prd.md` remains `status: draft` and includes open questions and
assumptions.

## DL-002: Canonical V2 release rule

Decision: Treat V2 as a single major release line with no intermediate releases.

Rationale: The user explicitly clarified that V2 is release-ready only when all
required V2 features are 100 percent done.

Impact: The PRD uses "V2 release scope" instead of "MVP scope" and treats
unresolved required scope as release-blocking decision gates.

## DL-003: Source precedence

Decision: Use `CONTEXT.md` and accepted ADRs as the durable source of truth,
then this master PRD and `docs/v2-scope-reconciliation.md`, then tracker state,
older BMAD artifacts, and V1 reference material.

Rationale: This preserves established domain language and avoids treating old
phase-local artifacts as the current release contract.

Impact: Accepted ADR 0008 remains required unless superseded; ADR 0016 and ADR
0020 keep direct Backend ciphertext streaming deferred until a Phase 5 decision.

## DL-004: Decision gates instead of silent scope decisions

Decision: Capture Content Scanner/Content Quarantine, multi-Shard boundary,
Phase 5 cold-read shape, `scrapctl` OpenBao bootstrap, and release
documentation/evidence standard as blocking gates.

Rationale: Party Mode aligned that the master PRD can be created now, but
implementation backlog generation must not proceed as if these decisions are
closed.

Impact: `bmad-create-architecture` is the next downstream workflow before
`bmad-create-epics-and-stories`.

## DL-005: Live tracker snapshot

Decision: Record the 2026-06-10 tracker state in the PRD.

Evidence:

- GitHub milestone `storage-gateway-v2`: open, `0` open issues, `110` closed.
- Open v2 issue found: `#429 Pre-v2 release: capture real S3/IAM production
  rehearsal evidence`.

Impact: Closed milestone issue count is treated as progress evidence, not V2
release closure.

## DL-006: Do not regenerate epics yet

Decision: Do not recreate `_bmad-output/planning-artifacts/epics.md` in this
step.

Rationale: The working tree already has the old Phase 4.5 epics file deleted,
and the master PRD still has blocking decision gates. Regenerating epics before
architecture decisions would produce unstable implementation stories.

Impact: Epics should be regenerated only after the required architecture gates
are resolved.
